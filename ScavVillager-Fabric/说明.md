# 老乡村民 Scav Villager · Fabric 客户端版

原 **Forge 模组**《老乡村民》（作者 **Arkit**）的 Fabric **纯客户端**移植。

- 只影响**装了模组的玩家**：服务器（包括原版服务器）和其他玩家都不需要装，也不需要 Fabric API。
- 语音**绑定在生物身上**，村民一边走一边说话——这是原模组的招牌效果，也是资源包做不到的部分。

## 安装

1. 客户端安装 Fabric Loader（对应你的游戏版本）
2. 把对应版本的 jar（在 **`成品/`** 目录里）放进 `.minecraft/mods/`：

| 游戏版本 | 用哪个 jar | 验证程度 |
| --- | --- | --- |
| 1.20.1 | `scav-villager-fabric-1.20.1-1.0.5.jar` | 实机验证过（1.0.4 时期进世界跑过；1.0.5 只是内部调用改走兼容层，编译验证） |
| 1.21 / 1.21.1 | `scav-villager-fabric-1.21-1.0.5.jar` | **实机启动验证**（进世界跑过） |
| 1.21.2 / 1.21.3 | `scav-villager-fabric-1.21.2-1.0.5.jar` | 编译 + mixin 目标解析验证 |
| 1.21.4 | `scav-villager-fabric-1.21.4-1.0.5.jar` | 编译 + mixin 目标解析验证 |
| 1.21.5 | `scav-villager-fabric-1.21.5-1.0.5.jar` | 编译 + mixin 目标解析验证 |
| 1.21.6 – 1.21.8 | `scav-villager-fabric-1.21.6-1.0.5.jar` | 同上（组内版本未逐一验证） |
| 1.21.9 – 1.21.11 | `scav-villager-fabric-1.21.9-1.0.5.jar` | 同上（组内版本未逐一验证） |
| **26.2** | `scav-villager-fabric-26.2-1.0.5.jar` | 编译 + **5 个 mixin 目标逐个比对存在**（游戏里未跑过） |

> **26.x 说明**（版本号从 1.21.11 之后改成年份制：26.1 / 26.1.1 / 26.1.2 / 26.2 / 26.3，**没有 "1.26.2" 这个版本**）：
> - 需要 **Java 25**（26.x 起 Mojang 用 Java 25 运行时）
> - **Minecraft 不再混淆**了：官方直接发布带官方类名的 jar（所以不需要映射表，也不需要 refmap）
> - 因此 26.2 是**独立的一套 Gradle 工程**：`../ScavVillager-Fabric-26/`（Gradle 9.8 + JDK 25 + Loom 1.18.2 的**去混淆版插件** `net.fabricmc.fabric-loom`），
>   共享同一份 `common/` 源码 —— 类名差异由 `../_toolchain/make_26_sources.py` 自动改写（`ResourceLocation`→`Identifier`、
>   实体类换子包、`GuiGraphics`→`GuiGraphicsExtractor` 等）
> - 26.2 上这些功能**都有**：语音跟随/警觉/战斗喊话/TNT/目击、进服音、玩家死亡音、成就与配方提示音、228 弹窗、入场提示框
>   （细节差异：入场提示框不再画老乡头像、228 弹窗的按钮用原版样式 —— 26.2 的贴图/按钮绘制 API 换成了渲染状态模型）

3. 不需要 Fabric API，不需要在服务器上装任何东西。

> **1.21.x 已全覆盖**（12 个稳定版）。每组的 jar 都按**组内最低版本**编译，
> 版本范围写在 `fabric.mod.json` 里（`>=1.21.2 <1.21.4` 这种）。
> 1.21.2 起服务端/客户端 API 有变动（`ToastComponent`→`ToastManager`、`SoundEvent.getLocation()`→`location()`、
> GUI 贴图 API 等），这些差异都收在各组自己的 `Compat.java` 里，共享代码只有一套。
>
> **新版本 jar 用宽容模式的 mixin 配置**（`required: false` + `require: 0`）：
> 万一某个小版本的目标方法对不上，**游戏照常能开**、只在该版本上少个功能，
> mixin 的告警会出现在日志里（搜 `Mixin` 就能看到）。1.20.1 和 1.21 这两个实测过的版本保持严格模式。

> **装了模组就别再装资源包**：`老乡村民音效包-*.zip` 和这个模组用的是同一套素材，
> 同时启用会重复注册同一批音效。另外那个包是 1.20.1 的 `pack_format 15`，
> 在 1.21 上会被游戏标成"不兼容"——直接删掉它，把位置让给模组。

## 复现了哪些功能

| 功能 | 触发条件 |
| --- | --- |
| 语音跟随实体 | 村民/掠夺者所有语音都绑定在生物身上播放，跟随移动 |
| 待机语音 | 175 条 idle、交易 yes/no/haggle、庆祝 celebrate |
| 受击 / 死亡 | 跟随原版 hurt / death；死亡语音会"脱钩"留在原地播完 |
| 警觉 alert | 村民察觉到玩家（默认 5 格）或敌意生物（默认 24 格）；掠夺者发现玩家/村民/铁傀儡 |
| 战斗喊话 fight | 掠夺者蓄弩、受击或追击中 → 进入战斗时喊 alert，战斗中每 2 秒一句 fight |
| 失去目标 clear | 掠夺者脱离战斗时喊 clear |
| TNT 恐慌 grenade | 8 格内出现点燃的 TNT |
| 目击死亡 witness | 同族（村民看村民 / 掠夺者看掠夺者）在 10 格内死亡 |
| 界面音效 | 成就 / 配方提示音替换；进入世界播 3 遍入场音频 + 弹入场提示框（"成就达成！"）；本地玩家死亡提示音 |
| 228 彩蛋 | 每 1200 tick 掷 1% 概率弹出塔科夫风"严重错误"窗，点确认回主菜单；`/228 test` 可手动触发 |
| 小村民变音 | 小孩语音音高 ×1.5（可关） |

大部分数值照抄原模组：优先级 GRENADE 40 / DEATH 35 / HURT 30 / 战斗 20 / IDLE 0、
绑定搜索半径 3.5 格、进服音频 96 tick 间隔播 3 遍、配方音延后 8 tick、
228 判定 1200 tick / 1%——配置默认值也与原模组一致。

## 没有实现的部分

- **TNT 躲避 AI**（村民、掠夺者主动跑开）：那是改服务端寻路，纯客户端做不到。
- **Guard Villagers 联动**（警卫村民语音）：那个模组的警卫是独立实体，需要单独适配；
  `enableGuard` / `guardSearchRange` 配置项保留，但目前不生效。
- 原模组里 `side=BOTH` 的服务端行为（客户端版全部改为观察客户端可见的状态来判断）。

## 配置

**游戏里可以直接开配置界面** ✓：聊天框输入 **`/scav`**（或 `/scav config` ✓）——
里面是开/关按钮，点一下**即时生效并写回配置文件** ✓，不用重启也不用重进世界。

| 按钮 | 关掉后会怎样 |
| --- | --- |
| **228 崩溃彩蛋** | 每 1200 tick 的随机判定完全不跑，不再弹窗 ✓ |
| 模组总开关 | 村民和掠夺者的语音**全部静音** ✓（原版那条也不播 ✓） |
| 村民语音 | 村民的待机/受击/死亡/交易/警觉等**全部静音** ✓ |
| 掠夺者语音 | 掠夺者的全部语音静音 ✓ |
| 成就 / 配方提示音 | 恢复原版提示音 ✓ |
| 进入世界的提示音 + 提示框 | 不再播入场音频、不弹入场框 ✓（**下一次进世界**生效 ✓） |
| 语音跟随实体 | 语音回到原版固定在触发点的行为 ✓（内容仍是这套语音 ✓） |
| 详细日志 | 关掉详细日志 ✓ |

> 语音类开关关掉时，**已经在播的那条会自然播完** ✓（不打断的设计 ✓）。
> 交易成交音（`deal.ogg`）属于村民语音，关掉村民语音时也会一起静音 ✓。

也可以直接编辑配置文件（下面这项就是同一个文件）：



路径 `config/scav_villager.json`，首次启动自动生成，**进入世界时会自动重载**（改完不用重启）。
键名和原模组完全一致，可以直接把老配置拷过来。常用项：

```json
{
  "enableMod": true,          // 总开关
  "enableVillager": true,
  "enablePillager": true,
  "volume": 1.0,              // 0.0 ~ 2.0（1.0 = 原音量）
  "babyPitch": true,          // 小村民变音
  "achievementSounds": true,  // 成就 / 配方提示音
  "joinSound": true,          // 进服三连音 + 入场提示框
  "playerDeathCooldownSeconds": 5,
  "error228Enabled": true,    // 想关掉 228 弹窗就改 false
  "verboseLog": false         // 排错时开 true，日志会打印每条语音的播放/丢弃
}
```

还有一批调参项（警觉/战斗/目击/TNT 的距离与冷却、扫描间隔 `checkIntervalTicks` 等），
名字和默认值都跟原模组一样，按需改。

## 修复记录

**1.0.1（务必用这个版本）**

1. 修掉"**进入世界就崩游戏**"的 bug。`Scheduler`（延迟任务调度器，进服三连音 / 配方音延迟 / 228 弹窗用它）
   原来边遍历边执行任务，而"播第一遍进服音"这个动作会再排一个新任务 → 列表被修改 →
   `ConcurrentModificationException` → 崩溃。现在改成"先把到期任务摘出来，再统一执行"。
   复现与回归测试见 `../_toolchain/SchedulerTest.java`（4 个场景：任务里排任务 / 多任务 / 延迟 / 动作抛异常）。
2. 给每 tick 的逻辑加了兜底 try/catch：音效模组再出错也只记日志（最多 5 条），不会把你游戏搞崩。
3. 入场提示框画图标时加了容错：贴图取不到就跳过图标继续显示（原来会直接抛异常）。

**1.0.2**：**掠夺者喊话降频**（实机反馈"触发过于频繁"）。三处原因，都改了：

1. **战斗判定太松**（主因）：早先拿"附近 8 格内有玩家"当"战斗中"，
   于是掠夺者只要站在你旁边就每 `fightGapSeconds` 秒喊一句战吼。
   原模组是服务端按**真实攻击目标**判定的。现在客户端改用「**正在蓄弩**（真在瞄准射击）或**最近挨过打**」
   判定，站着不动不再喊。
2. **`fightGapSeconds` 默认 2 秒 → 5 秒**（原模组默认是 2，想还原改成 2 即可）。
3. **alert 归位**：原来"进入战斗"会喊 alert，现在按原意改成「**发现敌人**」时才喊（60 秒冷却）；
   另外"失去目标"（clear）也加了冷却，免得在判定边缘来回走反复触发。

**1.0.3**：**修掉冷却时间单位错误**（这才是"触发过于频繁"的主因）。

配置里所有冷却都是以**秒**为单位，但传给调度器时我直接当成了 **tick**：
`5 秒` 实际只生效 `5 tick = 0.25 秒`，整整差了 20 倍 ✗。

| 配置 | 本意 | 1.0.2 以前的实际效果 |
| --- | --- | --- |
| `tntShoutCooldownSeconds = 5` | 5 秒 | 0.25 秒 |
| `fightGapSeconds` | 秒 | 只有 1/20 |
| `playerAlertCooldownSeconds = 60` | 60 秒 | 3 秒 |
| `witnessCooldownSeconds = 5` | 5 秒 | 0.25 秒 |
| `fightFleeSeconds`（clear 冷却） | 秒 | 只有 1/20 |

现在所有调用点统一走 `secondsToTicks()`（秒 × 20），各冷却**按配置的真实秒数生效**。
`tntShoutCooldownSeconds` 依旧是**每只生物各自** 5 秒（不是全域）。

**1.0.4**：**正在播放的语音不再被打断**。

原来同优先级/更高优先级的语音会把正在播的那条掐掉重放（听起来就是"半句话被切断"）。
现在改为：

- 这只生物正在说话时，**绝不打断**它；
- 新语音**排队等待**，等当前那条自然播完再放；
- 同一只生物只留**最新**的一条排队（后来的覆盖先前的），且排队**最多等 3 秒**
  （等超时就丢掉，免得战斗结束后突然冒出一句过期的喊话）；
- 生物消失/死亡时排队的语音一并丢弃。

副作用（如实说明）：挨打这类"应该马上出声"的语音，
现在要等当前那句话说完（最多 3 秒）才会响；如果当前语音超过 3 秒，这条就丢了。

**1.0.5 起：支持全部 1.21.x**（12 个稳定版本，见上面的安装表）。

做法是"一套共享源码 + 每组一个 `Compat` 垫片"：1.21.2 起 API 的变动都收在垫片里
（`ToastComponent`→`ToastManager`、`SoundEvent.getLocation()`→`location()`、GUI 贴图 API、
`disconnect(Screen)`→`disconnectWithSavingScreen()` 等）；toast 提示框在 1.21.2 起换了接口形态
（`render(GuiGraphics, Font, long)` + `getWantedVisibility()` + `update(...)`），所以入场提示框有两套实现；
成就提示音也有两套（1.21.2/1.21.4 用 `playedSound` 抢播，1.21.5+ 直接替换 `getSoundEvent()` 的返回值）。

**1.0.16**：**所有版本改回严格 mixin 模式**（`required: true` + `require: 1`）。

教训：宽容模式（`require: 0`）下"注入失败"是**完全静默**的 —— 1.21.6 / 1.21.9 上
放音拦截签名对不上、整个语音系统失效了好几轮，日志里却一个字都没有 ✗。
现在签名对不上会**当场报错** ✓，不会再静默失灵 ✓。

- 26.2 用严格模式**实机验证过** ✓：6 个 mixin 全部应用、客户端正常启动、零报错；
- 1.21.6 / 1.21.9 的拦截改用 `PlayResult` 形态 ✓（refmap 描述符逐个核对 ✓）。

**1.0.15**：**加一层兜底拦截**（`SoundEngine.play`）。26.2 里 `SoundManager.play` 只是转发给引擎 ✗，
而实际播放路径可能不经过上层 ✗ → 现在**上下两层都挂** ✓，哪层接住都行 ✓。

**1.0.14**：**修 1.21.6 / 1.21.9 上语音系统整体失效**（重要）。

排查过程：用户日志显示"点了产出槽"有记录，但**没有任何"分流"记录** ✗ ——
说明那条音效根本没进拦截逻辑 ✓。根因：

| 版本 | `SoundManager.play` 返回类型 |
| --- | --- |
| 1.20.1 – 1.21.5 | `void` |
| **1.21.6 / 1.21.9 / 26.2** | **`SoundEngine$PlayResult`** |

放音拦截的 mixin 写的是 `void` 形态 ✗ → 在 1.21.6 / 1.21.9 上**对不上、静默失效** ✗
（宽容模式 `require:0` 把它藏住了 ✗）→ **整个语音绑定（跟随/冷却/交易分流）在这两个版本上是死的** ✗。

现在按返回类型分了两份实现（`common/mixin-void` / `common/mixin-result`），26.2 另有一份
（它还把 `SoundInstance.getLocation()` 改名成了 `getIdentifier()`）。
**验证方式也补上了**：逐个检查 **refmap 里的方法描述符**，返回类型一眼可见 ✓
（之前只看"目标能不能解析"✗，而返回类型不匹配是**不会报错的** ✗）。

**1.0.12**：**成交音只在交易成功时响**（选中可交易商品时不再响）。

实测确认：原版的 `entity.villager.yes`（字幕村民：同意）**两个时机都会播**——
在交易界面**选中某件可交易的商品**、以及**交易成功**。事件本身分不出来，所以改用运行时信号：

- 新增 mixin `ContainerScreenMixin`：记下玩家点了交易界面的**产出槽**（索引 2）——点它就是执行交易；
- 点产出槽后 **0.8 秒内**到达的 `yes` → 播**成交音**（`deal.ogg`）；
- 其余 `yes`（选中商品时）→ 播**砍价语音**（新增内部事件 `scav_villager:entity.villager.haggle`，复用原来的 25 条）。

> `slotClicked` 的签名在各版本不同：1.20.1–1.21.9 是 `ClickType`，26.2 改名成 `ContainerInput`，
> 所以这个 mixin 有两份实现。

**1.0.11**：交易音效对应关系修正（**实测确定**，前面几版是推断错的）。

| 原版时刻 | 事件 | 字幕 | 播什么 |
| --- | --- | --- | --- |
| 点村民进交易界面（打招呼） | `entity.villager.trade` | 村民：交易 | 砍价语音 ✓ |
| **购买成交** | `entity.villager.yes` | 村民：同意 | **`deal.ogg`** ✓（每笔都响、可插播） |
| 卖不了（缺货 / 买不起） | `entity.villager.no` | 村民：拒绝 | 砍价语音 ✓ |

> 1.0.8–1.0.10 我把成交音配在了 `trade` 上，结果进交易界面就响成交音、真正成交反而放别的——
> 事件名和实际时机的对应关系只能靠实测确定，感谢反馈。

**1.0.9**：交易音效重新分配（按你的要求）。

| 时机 | 原版事件 | 现在播什么 |
| --- | --- | --- |
| **成交**（把物品交给村民） | `entity.villager.trade` | **只播 `deal.ogg`**（你给的"成交"音效） |
| **点选不同商品**（切换交易选项） | `entity.villager.yes` / `entity.villager.no` | **25 条砍价语音**（`haggle1..25`） |

原来的 yes（33 条）/ no（38 条）语音素材**保留在包里**，现在没有被引用 —— 想混进去或换回来都好办。
交易成交**不受待机冷却限制**，每笔都会响。

**1.0.8**：**交易成交音效换成你给的 `成交.mp3`**。

原始文件 48kHz 立体声 1.30 秒 → 转成**单声道 OGG Vorbis**（`mob/villager/deal.ogg`，16KB）：
降单声道是因为这是绑定在村民身上的 3D 定位音效；**不重采样**（保留原生 48kHz，零损失）；峰值 0.45，无削波。

**1.0.7**：修"**感觉不到冷却**"（小村民身上最明显）。

1.0.4 加的"不打断 + 排队"有个漏洞：**冷却只在真正播放时才检查**，
于是前面那句刚播完、冷却早就过去了，排队的那条立刻接上 —— 只要请求不断（小村民跟着玩家跑就是这种情况），
就能**一句接一句连下去**，听起来就像没有 CD。现在**排队前也查冷却**：冷却没到就直接丢弃、不进队列，
每只生物的每类语音都有硬性最小间隔。

顺带把日志补全了：开 `verboseLog: true` 时，每条"播放 / 排队 / 丢弃"都会带**生物名和原因**
（例如"冷却未到，丢弃（村民，还需 3 秒）"），方便判断频率到底是被什么挡住的。

**1.0.6**：修入场提示框"**文字和图片消失**"。

1. **文字**：颜色常量写成了 `0xFFFF55` / `0xFFFFFF`——少了不透明位（alpha = 0）。
   老版本 MC 会自动把它当成不透明处理，但新渲染管线下就是**完全透明**：面板（半透明 ✓）能看见，
   文字画了却看不见。现在改成 `0xFFFFFF55` / `0xFFFFFFFF`，全部 8 个 jar 一起修了。
2. **图片**：26.2 那边之前**故意没画**老乡头像（当时贴图 API 换成了渲染状态模型，我不想瞎猜参数）。
   现在用**原版按钮/容器界面同款的 `RenderPipelines.GUI_TEXTURED`** 把头像一个补回来了
   （已核对这个管线常量确实被原版 `AbstractButton`、`AbstractContainerScreen` 用来画贴图）。
   贴图取不到时依旧只跳过图标、不影响游戏。

**1.0.5**：**给死亡语音开例外**（1.0.4 的补充）。

死亡是这只生物的最后一句话，特批允许打断：立刻掐掉当前语音、丢掉排队的那条，**马上播死亡声**。
其他语音（挨打、警觉、战吼等）依旧遵守"不打断、排队等播完"的规则。

## 调参：嫌吵就改这几个

配置在 `config/scav_villager.json`，**进世界时自动重载**（不用重启）：

| 配置键 | 默认 | 作用 |
| --- | --- | --- |
| `fightGapSeconds` | 5 | 战斗喊话间隔（秒），调大更安静 |
| `ambientIntervalTicks` | 20 | 同一只生物待机语音的最小间隔（20 tick = 1 秒）；**0 = 按原版节奏**（约 4~6 秒一句，最安静） |
| `playerAlertCooldownSeconds` | 60 | 同一只生物"发现敌人"的冷却（秒） |
| `hostileAlertCooldownSeconds` | 60 | 村民警觉敌意生物的冷却（秒） |
| `tntShoutCooldownSeconds` | 5 | 看见点燃 TNT 的喊话冷却（秒，每只生物各自算） |
| `witnessCooldownSeconds` | 5 | 目击同伴死亡的喊话冷却（秒） |
| `enablePillager` | true | 直接关掉掠夺者全部语音（村民保留） |
| `enableVillager` | true | 关掉村民全部语音 |

例如想要"安静模式"：

```json
{
  "fightGapSeconds": 10,
  "ambientIntervalTicks": 0,
  "playerAlertCooldownSeconds": 180,
  "hostileAlertCooldownSeconds": 180,
  "tntShoutCooldownSeconds": 15,
  "witnessCooldownSeconds": 20
}
```

## 构建 / 改代码

**1.20.1 – 1.21.11（7 个分组，Loom 1.6.12）**：

```bash
export JAVA_HOME=/d/JAVA/Java21
cd ScavVillager-Fabric
../_toolchain/gradle-8.7/bin/gradle build          # 产物在各 v1_*/build/libs/
```

**26.2（独立工程，Loom 1.18.2 + Gradle 9.8 + JDK 25）**：

```bash
export JAVA_HOME=/c/Users/Admin/Downloads/SCAV/_toolchain/jdk-25.0.4.1+1
cd ScavVillager-Fabric-26
python ../_toolchain/make_26_sources.py           # 改过 common/ 共享代码后必须先跑，它会改写类名/包名
../_toolchain/gradle-9.8.0/bin/gradle build
```

工具链都在 `../_toolchain/`：`gradle-8.7`（JDK 21 用）、`gradle-9.8.0` + `jdk-25.0.4.1+1`（26.2 用）。
首次构建要联网下载 Minecraft 依赖（每个 MC 版本几百 MB，国内建议先看 `gradle.properties` 里的阿里云镜像配置）。

或者用 **IDEA** 打开 `ScavVillager-Fabric`（1.20.1–1.21.11）或 `ScavVillager-Fabric-26`（26.2），
Gradle 发行版在 *Settings → Build Tools → Gradle* 里选 "Specified location" 指向 `_toolchain` 下对应目录。

工程结构：共享代码在 `common/src/main/java`；1.21.2+ 的 toast 新形态在 `common/toast-new/java`。
每个版本分组一个子项目（`v1_20_1`、`v1_21`、`v1_21_2`、`v1_21_4`、`v1_21_5`、`v1_21_6`、`v1_21_9`），
各自只差一个 `Compat.java`（+ 旧形态 toast 那几份）；**26.2 在 `../ScavVillager-Fabric-26/`**，
源码由 `make_26_sources.py` 从 `common/` 自动改写生成。
新增游戏版本时照着建一个子目录即可。
